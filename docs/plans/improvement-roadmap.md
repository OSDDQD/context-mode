# context-mode — план улучшений

Дата: 2026-08-20. Основа: полный аудит дерева (src/ 46K строк, hooks/ 9.6K строк),
deep-dive retrieval-стека (fff / graph / search) и обзор экосистемы инструментов
экономии контекста (Serena, claude-context/Zilliz, aider repo map, Greptile,
octocode, RepoPrompt, LLMLingua, платформенные фичи Anthropic).

Цель: один плагин, который делает работу с кодом эффективной и не пускает в
контекст ничего лишнего — включая байты самого плагина.

---

## 0. Немедленно: расхождение установленной сборки и дерева

Хост в текущей сессии отдаёт **12** ctx_*-инструментов, дерево регистрирует **15**:
отсутствуют `ctx_find`, `ctx_graph`, `ctx_read` — три самых ценных инструмента
для кода. Их env-гейты включены по умолчанию, значит в plugin-кэше живёт старая
сборка. Механизм для этого уже есть (`src/util/delivery-health.ts`,
`EXPECTED_CTX_TOOLS`) — прогнать `ctx doctor` / `ctx upgrade` и убедиться, что
доставка чинится сама. Пока это не исправлено, вся ветка «код» плагина мертва
в реальных сессиях.

Мелочь туда же: в корне репозитория лежат `f0.tmp`, `f1.tmp`, `f2.tmp` — мусор.

## 2. Расход контекста самим плагином — самая крупная статья

Парадокс: плагин экономии контекста сам вливает в сессию:

| Блок | Байт | ~токенов |
|---|---|---|
| SessionStart routing-блок | 8 530 | 2 133 |
| Блок в промпт **каждого** сабагента | 7 485 | 1 871 |
| Описания инструментов (уже compact) | 5 644 | ~1 400 |
| `skills/context-mode/SKILL.md` | 18 175 | ~4 500 (по срабатыванию) |
| `CLAUDE.md` проекта | 4 523 | ~1 100 |

Сессия с пятью сабагентами — ~50 КБ служебного текста. Для описаний
инструментов бюджет-механизм уже сделан (форк-изменение №4, −73%); для
routing-блока аналога нет.

Предложения:

1. **Компактный routing-блок** по образцу compact tool descriptions: полная
   версия остаётся справкой, отгружается таблица. Цель ≤ 3 КБ. Env-переключатель
   назад. Тест на размер, как `compact-descriptions.test.ts`.
2. **Дифференцированный блок для сабагентов**: сабагенту не нужны секции про
   memory/resume/ctx-команды — только правила маршрутизации. Цель ≤ 1.5 КБ.
3. **SKILL.md по канону progressive disclosure** (Agent Skills): короткое тело,
   справочники — в подгружаемых файлах рядом.
4. **Политика отчётов сабагентов**: правило «файл + 1 строка» распространить и
   на возврат сабагентов (инъекция в routing-блок Agent) — многословные отчёты
   сабагентов заливают родителя так же, как сырые tool outputs.

## 3. Заимствования из экосистемы

Проверено против уже сделанного в форке (35 изменений) — дубликатов нет.

### 3.1 Токен-бюджетная карта репозитория (aider repo map) — приоритет №1

`ctx_graph(action: "map", budget: 1024, focus: "retry handling")`.
Механика aider: граф «файлы, связанные через символы», персонализированный
PageRank (термины запроса ×10), выдача — файлы + сигнатуры важнейших сущностей,
сжатые под токен-бюджет. **Codegraph-БД уже есть** — нужен только алгоритм
поверх `nodes`/`edges`. Это ответ на вопрос «покажи структуру проекта» ценой
1 КБ вместо серии Read. Стоимость: M.

### 3.2 Тело символа по имени (Serena find_symbol / octocode view_signatures)

Три уровня выдачи вместо двух: список файлов → **сигнатуры/силуэт** → тело
одного символа. `ctx_graph(action: "outline")` уже даёт силуэт; добавить
`action: "body"` (или `ctx_read(symbol: "ClassName.method")`): по codegraph
известны `file_path` + `start_line`/`end_line`, тело режется в песочнице.
Закрывает главный сценарий утечки: «покажи функцию X» → Read всего файла.
Стоимость: S.

### 3.3 AST-границы чанков при индексации кода (claude-context/Zilliz, Cursor)

`#chunkFile` (`src/store.ts:2347`) режет исходники текстовыми стратегиями.
Codegraph уже знает границы символов — чанковать `code:<relpath>` по границам
функций/классов (fallback на текущую стратегию без индекса). Точность
ctx_search/ctx_find по коду вырастает без новых зависимостей. Стоимость: M.

### 3.4 Кэш повторных чтений (идея lean-ctx, шов уже готов)

`PathCache` в fs-bus (`src/fs-bus/index.ts:570`) — пустой реестр «на будущее».
Реализовать: повторный Read/ctx_read неизменённого файла (инвалидация от
watcher'а бесплатна) отвечает «не изменился с последнего чтения, hash X» вместо
повторного содержимого. lean-ctx заявляет, что повторные чтения — одна из
крупнейших статей расхода. Стоимость: M.

### 3.5 Рецепт ревью «от диффа наружу» (Greptile)

Skill/команда: diff → `ctx_graph impact` → callers → git-история затронутых
файлов, пока изменение не «сойдётся». Чистая композиция существующих
инструментов, кода почти нет. Стоимость: S.

### 3.6 Атрибуция потерь в ctx_stats (claude-context-optimizer)

Missed-redirect телеметрия уже есть (форк №2). Добавить вторую метрику:
«прочитано, но не использовано» — файлы, попавшие в контекст через Read и ни
разу не упомянутые в последующих Edit/ответах. `reuse-detector.ts` уже решает
родственную задачу. Стоимость: M.

### 3.7 ctx_pack — контекст-пакет под бюджет (RepoPrompt Context Builder)

`ctx_pack(task, budget)`: карта (§3.1) + сигнатуры (§3.2) + релевантные чанки
из KB, упакованные под N токенов — готовый промпт для сабагента. Синергия с
уже существующей инъекцией routing-блока в Agent. Стоимость: M (после 3.1/3.2 — S).

### 3.8 Чего НЕ делать (платформа закрыла)

- Ленивая загрузка tool-схем — Tool Search Tool / deferred tools уже в хосте.
- LLMLingua-подобное ML-сжатие — дороже, чем «выполни код и напечатай ответ».
- Пост-фактум суммаризация tool output — PostToolUse не может модифицировать
  вывод (issues anthropics/claude-code #4544, #18594, #31279, #32105).
  PreToolUse-редирект context-mode — единственный рабочий подход; за issue про
  `updatedToolOutput` следить как за будущей второй линией.
- Чистка истории — context editing / memory tool / microcompact делают это
  нативно; ниша плагина — профилактика (не пускать байты вовсе), конфликта нет.

## 4. Консолидация в «один плагин»

1. **fff-mcp как отдельный глобальный сервер — дубликат.** Плагин использует
   fff in-process (`@ff-labs/fff-node`), а `~/.claude.json` поднимает ещё и
   `fff-mcp` (3 инструмента, отдельный процесс, свои схемы в каждом запросе),
   и глобальный CLAUDE.md велит им пользоваться. После починки доставки
   `ctx_find` (§0) глобальный fff-mcp и инструкцию можно убрать: `ctx_find`
   покрывает file-search + grep + ещё три сигнала одним инструментом.
2. **codegraph остаётся внешним** — read-only потребление его SQLite со
   схема-пиннингом чисто и правильно. Но добавить в `ctx_doctor`/первый вызов
   `ctx_graph` явное «индекса нет → выполни `codegraph init`» (сейчас деградация
   молчаливая, и половина сигналов слепнет незаметно).
3. **server.ts (4808 строк)** — довести вынос инструментов в `src/tools/*` до
   конца (7 осталось inline); контракт `ToolDeps` уже есть.
4. **135 env-флагов CONTEXT_MODE_*** — сгенерировать справочник (таблица:
   флаг / дефолт / слой / когда трогать), схлопнуть семейства-пятёрки
   (reuse-detector) до одного JSON-флага.
5. **docs/FORK-CHANGES.md (137 КБ)** → структурированные ADR в пустующем
   `docs/adr/`.
